# High-Level System Design

## 1. Architecture

The application will follow a client-server architecture:

- **Client:** An Android application built with the **Kivy** framework in Python. This client will be responsible for the user interface and user interactions.
- **Backend:** Google's **Firebase** will be used for all backend services to ensure scalability and reliability.
  - **Authentication:** Firebase Authentication will handle user sign-up, login, and session management.
  - **Database:** Cloud Firestore will be used as the NoSQL database for storing all application data, including user information, reminders, and bookings.

## 2. Data Models

The data will be structured in Firestore as follows:

### Users Collection

This collection will store basic information about each user.

- **Collection Path:** `users`
- **Document ID:** `user_id` (The UID from Firebase Authentication)
- **Fields:**
  - `email` (string): The user's email address.
  - `created_at` (timestamp): The timestamp of when the user account was created.

### Reminders Sub-collection

Each user will have their own sub-collection of reminders.

- **Collection Path:** `users/{user_id}/reminders`
- **Document ID:** `reminder_id` (Auto-generated by Firestore)
- **Fields:**
  - `title` (string): The title of the reminder.
  - `description` (string): A more detailed description of the reminder.
  - `reminder_time` (timestamp): The date and time for the reminder to trigger.
  - `created_at` (timestamp): The timestamp of when the reminder was created.
  - `is_active` (boolean): A flag to enable or disable the reminder.

### Bookings Sub-collection

Each user will also have a sub-collection for their bookings.

- **Collection Path:** `users/{user_id}/bookings`
- **Document ID:** `booking_id` (Auto-generated by Firestore)
- **Fields:**
  - `booking_type` (string): The type of booking (e.g., "Flight", "Train", "Bus", "Hotel").
  - `confirmation_number` (string): The booking reference or confirmation number.
  - `departure_date` (timestamp): The start date/time of the booking.
  - `arrival_date` (timestamp): The end date/time of the booking.
  - `notes` (string): Any additional notes or details about the booking.
  - `created_at` (timestamp): The timestamp of when the booking was added.

## 3. Security Considerations

### Firestore Security Rules

To ensure that users can only access their own data, it is **critical** to implement Firestore Security Rules on the backend. The application's security model relies on these rules to prevent unauthorized data access.

Here is a basic example of the security rules that should be configured in your Firebase project's Firestore Database settings:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Users can only read and write to their own user document
    match /users/{userId} {
      allow read, write: if request.auth.uid == userId;

      // Users can only read and write their own reminders and bookings
      match /{subcollection}/{documentId} {
        allow read, write: if request.auth.uid == userId;
      }
    }
  }
}
```
